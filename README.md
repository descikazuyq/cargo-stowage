# 本地舱单与配载

这是一个在本机运行的本地舱单与配载 Go 模块。登记处以编号管理舱位
（最大承重，千克）与货物（重量、目的地、是否允许混装），并提供：

- **配载调整 `Adjust`**：一次提交可包含多件货物的装载、卸下与移动，
  按全部操作完成后的最终配载统一校验承重与混装限制，任一操作不合法
  则整次不生效；成功后返回货物与舱位的变化记录，并以调整编号支持
  安全的重复提交。
- **提交前预览 `Preview`**：只读预演一批安排，给出能否提交、预计
  配载与全部拒绝原因，不改变状态、不占用编号。
- **货物资料更正 `AmendCargo`**：按现有货物编号整体替换重量、目的地
  与混装许可，货物编号与所属舱位不变。
- **状态查询**：随时查询货物当前所在舱位，以及舱位的承重、已用与
  剩余重量和货物清单。

## 使用

```bash
go test ./...
```

测试通过即表示模块可用；各文档中的 Go 示例均为包内示例测试，可用
上面的命令直接验证输出。

## 文档

- [正式提交调整与同一编号的再次提交](docs/commit-adjustment.md)：
  如何读懂 `Adjust` 成功返回的变化记录；同一调整编号以原内容再次提交
  时为什么返回首次结果却不重新装卸，什么算原内容（货物、操作种类、
  装载/移动目标相同即可，顺序无关；编号去空白后比较且区分大小写；
  卸下目标不参与比较）；同一编号换内容时如何读出"调整编号冲突"的
  结构化错误；以及第一次就失败的调整为何不占用编号。文中的 Go 示例
  与 `stowage/example_adjust_test.go` 对应。
- [配载被拒绝时怎样读懂错误](docs/adjust-rejection.md)：每条装卸操作
  本身合法、但整批安排完成后的最终配载违反承重或混装限制时，如何
  读懂 `Adjust` 返回的唯一一个结构化错误（没有成功结果）：先按舱位
  编号字典序选择最靠前的违规舱位、同一舱位先报告重量问题，且与操作
  排列顺序无关；超重与重量溢出指向舱位、混装冲突指向舱内编号最靠前
  的不允许混装货物（可能是原舱货物而非本次新加入的货物），以及
  `Kind`、涉及对象、调整编号与中文说明分别怎么读；如何用 `Preview`
  一次看到全部拒绝原因；为什么拒绝后查询仍是提交前的配载。文中的
  Go 示例与 `stowage/example_adjust_rejection_test.go` 对应。
- [提交前核对配载安排](docs/preview-check.md)：如何用 `Preview` 在正式
  提交前预览一批配载安排、读懂预计结果与拒绝原因，以及预览与正式
  提交（`Adjust`）的关系。文中的 Go 示例与
  `stowage/example_preview_test.go` 对应。
- [更正已登记货物的资料](docs/amend-cargo.md)：如何用 `AmendCargo`
  按现有货物编号整体替换重量、目的地与混装许可，读懂更正后的查询
  结果与结构化拒绝原因，并确认失败的更正不影响原来的配载。文中的
  Go 示例与 `stowage/example_amend_test.go` 对应。

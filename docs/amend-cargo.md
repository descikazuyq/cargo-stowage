# 更正已登记货物的资料

货物登记之后，重量、目的地或混装许可有时需要更正。本文说明如何用
`stowage` 包的 `AmendCargo` 完成一次更正、读懂更正后的查询结果，并
判断一次失败的更正是否影响了原来的配载。文中示例均为完整可运行的
Go 代码，与 `stowage/example_amend_test.go` 中的示例一一对应，可用
`go test ./...` 直接验证输出。

## 更正是整体替换，不是登记也不是调舱

`AmendCargo(id, weight, destination, allowMixed)` 按**现有货物编号**
把重量、目的地、混装许可**三项资料作为一次整体替换**生效：

- 货物**编号不变**，所属舱位也不变。未装载的货物更正后仍未装载；
  已装载的货物更正成功后仍留在原舱位。要改装载位置请用 `Adjust`
  的卸下/移动操作，更正不管舱位归属。
- 三项资料一起提交、一起生效。即使只想改其中一项，也要把另外两项
  的当前值一并传入；与现有资料完全相同的更正同样成功，不新增货物、
  不再次占用重量。
- 更正不占用调整编号，也不影响已成功调整保存的结果。

资料规则与登记一致：重量必须是**正整数，单位为千克**；货物编号与
目的地都会**去掉首尾空白**后识别和保存；编号**区分大小写**（`g1`
与 `G1` 是两件不同的货物）。空编号、不存在的货物、非正重量、去空白
后为空的目的地都会被拒绝。

### 两个入口各自做什么

登记和更正是两个不同的入口，互不替代：

- `RegisterCargo` 只负责**登记新货物**。用已有编号再次登记会被拒绝
  （`ErrAlreadyExists`），**不会**覆盖原有资料——想改资料必须用
  `AmendCargo`。
- `AmendCargo` 只负责**更正已登记的货物**。货物编号不存在时被拒绝
  （`ErrNotFound`），**不会**自动登记一件新货物——想登记新货物必须
  用 `RegisterCargo`。

## 主示例：更正一件已装载货物的三项资料

场景从新建登记处开始，不依赖任何已有状态：登记承重 100 千克的舱位
C1，再登记两件目的地不同、都允许混装的货物——G1 30 千克去上海、
G2 20 千克去北京——并通过一次正式调整把两件都装入 C1（目的地不同
但都允许混装，共舱合法），此时 C1 已用 50 千克：

```go
reg := stowage.NewRegistry()
reg.RegisterCompartment("C1", 100)
reg.RegisterCargo("G1", 30, "上海", true)
reg.RegisterCargo("G2", 20, "北京", true)
_, err := reg.Adjust("load-1", []stowage.Op{
    {Kind: stowage.OpLoad, CargoID: "G1", Target: "C1"},
    {Kind: stowage.OpLoad, CargoID: "G2", Target: "C1"},
})
// err == nil：初始装载完成，C1 已用 50/100 千克。
```

现在对已装载的 G2 做一次更正，三项资料同时改：重量 20 → 40 千克、
目的地 北京 → 上海（与同舱的 G1 相同）、混装许可 允许 → 不允许：

```go
err := reg.AmendCargo("G2", 40, "上海", false)
```

更正前后分别查询该货物和所属舱位（对应 `Example_amendLoadedCargo`）：

```
更正前: G2 重量 20 千克、目的地 北京、允许混装 true、所在舱位 C1
更正前: 舱位 C1 已用 50 千克、剩余 50 千克
更正返回错误: <nil>
更正后: G2 重量 40 千克、目的地 上海、允许混装 false、所在舱位 C1
更正后: 舱位 C1 已用 70 千克、剩余 30 千克
```

读法：

- **重量是替换，不是累加。** 舱位先扣除 G2 的旧重量、再计入新重量：
  50 − 20 + 40 = 70 千克，剩余 30 千克。新重量不会被再累计一次
  （不是 50 + 40 = 90）。
- **货物留在原舱位。** G2 已装载，更正成功后 `CompartmentID` 仍是
  C1；未装载的货物更正后同样保持未装载。
- **承重与混装按更正后的完整资料共同判断。** 判断针对的是三项新资料
  一起生效后的最终配载，而不是逐字段的中间状态。这里目的地改成与
  G1 相同（都是上海）之后，同舱货物目的地一致，**不要求**任何货物
  允许混装，所以可以同时取消 G2 的混装许可——若按"先取消混装、再
  改目的地"的中间状态判断，这一刻目的地仍不同，反而会被误拒。
- **恰好用满承重是允许的。** 例如把 G2 更正为 70 千克，舱位合计
  30 + 70 = 100 千克，恰好等于承重，更正成功、剩余 0 千克（对应
  `Example_amendExactCapacity`）——只有**超过**承重才算超重。

## 被拒绝的更正一：新重量使当前舱位超重

在同一组初始配载上（C1 已用 50/100 千克），把 G1 更正为 90 千克，
舱位预计合计 90 + 20 = 110 千克，超过承重 100 千克（对应
`Example_amendOverweightRejected`）：

```go
err := reg.AmendCargo("G1", 90, "上海", true)
```

```
拒绝原因: 超重
涉及编号: C1
说明: 舱位 C1 总重量 110 千克超过最大承重 100 千克
G1 仍是 30 千克、目的地 上海、允许混装 true、所在舱位 C1
舱位 C1 已用 50 千克、剩余 50 千克
```

`AmendCargo` 失败时返回结构化错误 `*stowage.Error`，用
`errors.As` 取出后：`Kind` 给出原因（这里是 `ErrOverweight`），
`ID` 给出**涉及的编号**——超重时指的是**装不下的舱位**（C1），
不是被更正的货物；`Error()` 给出可直接阅读的中文说明，包含舱位、
预计总重量与承重。

**失败不影响原来的配载。** 更正失败后查询：G1 的三项旧资料（30 千克、
上海、允许混装）、所在舱位 C1、舱位已用 50 千克全部保持原样，同舱
其他货物也不受影响。可以修正资料后再次提交更正。

## 被拒绝的更正二：目的地仍不同时取消混装许可

仍在初始配载上（G1 上海、G2 北京，靠全员允许混装共舱），只取消 G1
的混装许可而目的地保持不同（对应 `Example_amendMixedConflictRejected`）：

```go
err := reg.AmendCargo("G1", 30, "上海", false)
```

```
拒绝原因: 混装冲突
涉及编号: G1
说明: 舱位 C1 存在不同目的地货物，但货物 G1 不允许混装
G1 仍是 30 千克、目的地 上海、允许混装 true、所在舱位 C1
舱位 C1 已用 50 千克、剩余 50 千克
```

不同目的地共舱时，**所有**货物都必须允许混装。更正后 G1 不允许混装
而目的地仍与 G2 不同，最终被拒。此时结构化错误的 `Kind` 是
`ErrMixedLoading`，`ID` 指的是**不允许混装的那件货物**（G1）——
与超重时指向舱位不同，读 `ID` 前先确认 `Kind`。失败后同样一切保持
原样：三项旧资料、装载位置、舱位重量均未改变。

对比主示例可以看到同一条规则的两面：目的地改成一致后取消混装许可
合法（主示例），目的地仍不同时取消则被拒（本例）。

## 更正之后的查询、预览与旧快照

- 更正成功后，**新的查询和新的预览都按新资料**：`Cargo`、`Compartment`
  返回更正后的重量、目的地与混装许可，`Preview` 与 `Adjust` 的承重、
  混装判断也使用更正后的资料。
- 更正**之前**返回的查询结果（`CargoView`、`CompartmentView`）和预览
  结果（`PreviewResult`）是独立快照，**仍保留原内容**，不会随后续
  更正而变化；调用方修改这些快照也不影响登记处。需要最新资料时重新
  查询即可。

## 与预览文档的关系

更正改的是货物**资料**，预览（`Preview`）预演的是货物**位置**安排，
两者互补：更正后想再调整装载位置，可先按新资料预览再提交。预览的
用法见[提交前核对配载安排](preview-check.md)。

# 更正已登记货物的资料

货物登记之后，重量、目的地或混装许可有时需要更正。本文说明如何用
`stowage` 包的 `AmendCargo` 完成一次更正、如何读懂更正后的查询结果、
被拒绝时结构化错误里的编号指什么，以及怎样确认一次失败没有影响原来的
配载。文中示例均为完整可运行的 Go 代码，与
`stowage/example_amend_test.go` 中的示例一一对应，可用
`go test ./...` 直接验证输出。预览（`Preview`）与正式提交（`Adjust`）
的用法见[提交前核对配载安排](preview-check.md)，本文不再重复。

## 更正与登记是两个入口

两件事最容易混淆，先分清楚：

- **登记新货物用 `RegisterCargo`**。编号已存在时返回 `ErrAlreadyExists`
  （`对象已存在`），**原资料原样保留，不会被新参数覆盖**；想改资料不能
  重新登记一次。
- **更正已有货物用 `AmendCargo(id, weight, destination, allowMixed)`**。
  它按**现有货物编号**找到货物，把**重量、目的地、混装许可三项资料作为
  一次整体替换**写入：只想改一个字段时，也要把另外两个字段按现值一并
  传入。编号不存在时返回 `ErrNotFound`（`对象不存在`），**更正不会变成
  登记**，不会凭空新增一件货物。

```go
reg.RegisterCargo("G1", 20, "北京", true)   // 首次登记：成功
reg.RegisterCargo("G1", 99, "上海", false)  // 重复登记：ErrAlreadyExists，G1 仍是 20/北京
reg.AmendCargo("G9", 30, "广州", true)      // 货物不存在：ErrNotFound，不会登记出 G9
reg.AmendCargo("G1", 25, "上海", false)     // 更正已有货物：三项整体替换
```

参数规则与登记时一致：

- **重量**是正整数千克；`0` 或负数返回 `ErrInvalidWeight`。
- **编号与目的地**都先去掉首尾空白再识别，去空白后为空分别返回
  `ErrInvalidID`、`ErrInvalidDestination`；传入 `" G1 "` 与 `"G1"`
  命中同一件货物，但保存与展示的始终是去空白后的 `"G1"`。
- **编号区分大小写**：`g1` 与 `G1` 是两件不同的货物，更正 `G1` 不会
  影响 `g1`。

更正保持两件东西不变：

- **货物编号不变**，也不新增、不删除货物记录；
- **所属舱位不变**：未装载货物更正后仍未装载；已装载货物更正成功后仍
  留在原舱位，只是该舱按新资料重新计重、重新判断混装。更正不是装卸
  操作，**不占用调整编号**，也不改变已成功调整保存的结果快照。

## 主示例：一次更正已装载货物的三项资料

场景从新建登记处开始：C1 承重 50 千克；G1 重 20 千克、去北京、允许
混装，G2 重 10 千克、去上海、允许混装；一次调整把两件都装入 C1。
它们目的地不同，但**全员允许混装时不同目的地可以共舱**，舱位为
30/50 千克：

```go
reg := stowage.NewRegistry()
reg.RegisterCompartment("C1", 50)
reg.RegisterCargo("G1", 20, "北京", true)
reg.RegisterCargo("G2", 10, "上海", true)
reg.Adjust("load-1", []stowage.Op{
    {Kind: stowage.OpLoad, CargoID: "G1", Target: "C1"},
    {Kind: stowage.OpLoad, CargoID: "G2", Target: "C1"},
})
```

现在对 G1 一次更正三项资料：20 千克、北京、允许混装 → 25 千克、上海、
不允许混装：

```go
err := reg.AmendCargo("G1", 25, "上海", false)
```

更正前后分别用 `Cargo` 查货物、用 `Compartment` 查舱位，得到
（对应 `Example_amendCargo`）：

```
== 更正前 ==
货物 G1：20 千克，去 北京，允许混装，在舱位 C1
货物 G2：10 千克，去 上海，允许混装，在舱位 C1
舱位 C1：[G1 G2]，已用 30 千克，剩余 20 千克（承重 50）
== 更正后 ==
货物 G1：25 千克，去 上海，不允许混装，在舱位 C1
货物 G2：10 千克，去 上海，允许混装，在舱位 C1
舱位 C1：[G1 G2]，已用 35 千克，剩余 15 千克（承重 50）
```

读法：

- **编号与位置不变**：G1 仍在 C1，货物清单仍是 `[G1 G2]`；变的只是
  G1 的三项资料。
- **重量是替换，不是累加**：舱位先扣除 G1 的旧重量 20、再计入新重量
  25，所以已用重量是 25+10=**35**、剩余是 50-35=**15**；不是在原来的
  30 上再压上一份新重量（30+25=55）。即使三项资料与原来完全相同，更正
  也会成功，同样不会把重量再计一次。
- **重量与混装按更正后的完整资料共同判断**：G1 的目的地改成与 G2 相同
  的上海后，全舱只有一个目的地，于是可以**同时取消 G1 的混装许可**。
  同一目的地共舱不要求所有货物都允许混装——G1 不允许、G2 允许，照样
  合法。混装许可只在舱内出现**不同**目的地时才被全员要求。
- 三项是作为一个整体按**最终配载**判断的，不会因为“先关掉混装、目的地
  还没改好”这类逐字段中间状态而拒绝一个最终合法的更正。

### 承重恰好用满是允许的

接着把 G1 改成 40 千克：10(G2)+40(G1)=50，恰好达到 C1 的承重，
更正成功，剩余重量为 0：

```
== 承重恰好用满 ==
货物 G1：40 千克，去 上海，不允许混装，在舱位 C1
舱位 C1：[G1 G2]，已用 50 千克，剩余 0 千克（承重 50）
```

“恰好达到承重”与“超重”是两回事：`剩余 == 0` 合法；只有预计总重量
**大于**承重才会被拒。

## 被拒情况一：新重量会使当前舱位超重

仍从 30/50 的初始配载开始，把 G1 从 20 千克改成 45 千克（目的地与混装
许可不变）：45+10=55 > 50（对应 `Example_amendRejectedOverweight`）：

```go
err := reg.AmendCargo("G1", 45, "北京", true)
```

```
更正被接受: false
错误原因: 超重
涉及编号（超重时为所属舱位）: C1
说明: 舱位 C1 总重量 55 千克超过最大承重 50 千克
货物 G1：20 千克，去 北京，允许混装，在舱位 C1
舱位 C1：[G1 G2]，已用 30 千克，剩余 20 千克（承重 50）
```

读法：

- `AmendCargo` 失败时返回与其他操作相同的结构化错误 `*stowage.Error`，
  用 `errors.As` 取出。`Kind` 是给程序判断的原因（这里是
  `ErrOverweight`，打印为“超重”），`Error()` 本身是可读的中文说明，
  直接给出舱位、预计总重量与承重。
- **`ID`（涉及编号）的含义随原因变化**：超重是**舱位整体**的状态，所以
  这里的 `ID` 是所属舱位 `C1`，不是被更正的货物 G1。重量合计溢出
  int64 时原因是 `ErrOverflow`，`ID` 同样指向舱位。
- 失败后查询即可确认原配载未受影响：G1 的三项旧资料（20、北京、允许
  混装）、位置（仍在 C1）、舱位已用 30 与剩余 20 全部保留。

## 被拒情况二：目的地仍不同，却取消混装许可

初始配载里 G1 去北京、G2 去上海，两件都允许混装。若把 G1 的混装许可
改为不允许、而目的地仍保持北京，最终配载就是“不同目的地共舱，但 G1
不允许混装”，更正被拒（对应 `Example_amendRejectedMixed`）：

```go
err := reg.AmendCargo("G1", 20, "北京", false)
```

```
更正被接受: false
错误原因: 混装冲突
涉及编号（混装冲突时为不允许混装的货物）: G1
说明: 舱位 C1 存在不同目的地货物，但货物 G1 不允许混装
货物 G1：20 千克，去 北京，允许混装，在舱位 C1
货物 G2：10 千克，去 上海，允许混装，在舱位 C1
舱位 C1：[G1 G2]，已用 30 千克，剩余 20 千克（承重 50）
```

读法：

- 混装冲突时 `ID` 指向**那件不允许混装的货物**（这里是 G1 本身；同舱
  有多件不允许混装的货物时，取编号字典序最靠前的一件），说明文字同时
  给出冲突所在的舱位 C1。被点名的不一定是“被更正的那件”，而是最终
  配载里不满足混装要求的货物。
- 对比主示例：同样是“不允许混装”，把目的地一并改成与 G2 相同的上海就
  合法；保持北京（与 G2 不同）就被拒。差异只在更正后舱内是否还存在
  不同目的地。
- 失败后逐项回查：G1 的三项旧资料、G2 的资料、两件的位置，以及 C1 的
  30/20 千克，全部与更正前一致。更正失败是一次整体失败，不会只写入
  其中一两个字段。

若一次更正同时超重又触发混装冲突，报告顺序与 `Adjust` 一致：先重量后
混装，即先收到 `ErrOverweight`。

## 更正之后：新查询与新预览用新资料，旧快照不变

更正影响的是登记处里的**当前资料**：更正成功之后新发起的 `Cargo`、
`Compartment` 查询与 `Preview` 预览都按新重量、新目的地、新混装许可
计算；后续的装载、卸下、移动（`Adjust`）同样按新资料执行。

但更正**不会追溯改写**此前已经返回给调用方的快照。下面的示例在更正前
先保留一份查询快照和一份“把 G1 移到 C2”的预览（C2 承重 22，旧重量
20 可移入），把 G1 更正为 25 千克后再预览同一清单并对照旧快照
（对应 `Example_amendSnapshotAndPreview`）：

```
更正前旧预览可提交: true
旧预览中 G1 移到 C2 后预计已用: 20 千克
更正后新预览可提交: false
新预览中 C2: 25/22 千克，超重 3 千克
旧预览快照未变: G1 20 千克 去 北京
更正前查询快照未变: G1 20 千克 去 北京，C1 已用 30 千克
货物 G1：25 千克，去 上海，不允许混装，在舱位 C1
舱位 C1：[G1 G2]，已用 35 千克，剩余 15 千克（承重 50）
```

读法：

- 同一清单（G1 移到 C2）在更正前预览可提交、更正后预览超重 3 千克。
  预览始终按调用时刻的资料现场计算，资料变了结论就可能变。
- 手里那份旧预览、旧查询快照仍保留更正前的 20 千克、北京；它们是独立
  副本，不会被后续更正改写，调用方修改它们也不影响登记资料。
- 预览是只读的：两次预览之后 G1 实际仍在 C1。要看真实当前状态，重新
  调用 `Cargo`/`Compartment` 即可。

因此，若在预览之后、正式提交之前发生过更正（或另有调整生效），旧预览
不构成提交必然成功的保证；这一点与[预览文档](preview-check.md)的说明
一致，提交前重新预览一次即可。
